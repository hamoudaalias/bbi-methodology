# Lesson 62 — Pre-sealed the verdict mapping for a devel secondary shortfall

**When :** Episodic memory J1-J4-P11, 2026-09-18 (E-W-C-P-L-A-T-I-K·A²·P_seq·P_learn·M_ep, Phase 11 AGI), sealed spec `b073bac0…` (Road A). J4-P11 on the holdout **91900-91999** : CE1 20/20 (`ea03050bca6b…`), **CE2-P11 = 0.667** on the B-discriminant class (floor 0.60 ; all-holdout 0.520), 20 probe-equiv fail cold → all 20 warm-resolve ; **G_memory = 0.667** (P_learn probes : warm 13 vs cold 39, CI (0.517, 0.817), LB 0.517 > δ=0.20, n=39) ; **G(P_seq) = 0.110** (nodes : warm 16 880 vs cold 18 958, CI (0.026, 0.136), LB 0.026 > 0) ; CE3 100 % (0 forcing, warm-unverified 0, no-harm 1.000 ≥ 1.000) ; CE4 secondary pre-mapped → PARTIEL (precision 1.000 / recall 0.693) ; CE5 mem 32 ≤ 32, probes {0:81, 1:19} ≤ 2, nodes 37 187 ≤ 50 000 ; F-1..F-4 not hit → **verdict POSITIF** — the **11ᵉ AGI property, second POSITIVE verdict of the trajectory** (episodic memory by causal structure, 0 DL).

**Context / tension :** on DEV the instrumented run showed a **probable per-channel secondary shortfall** : G(P_seq) nodes = 0.011 with CI95 LB ≤ 0 (−0.016, 0.054) — the seed-reuse channel looked neutral. Two readings were in conflict : the sealed spec §3 tags P_seq *« evaluated as a diagnostic, never as a primary claim »* (no secondary node demand for POSITIF), while the CP GO grid asked per-channel G(P_seq) LB > 0 for POSITIF. Rather than argue at measurement time (the classic confirmation-bias window), the J4 script pre-registered the mapping **before the holdout opened** : primary grid satisfied ∧ secondary LB ≤ 0 ⇒ **PARTIEL + ALERTE CP** (arbitration demand), never a NEGATIF (no negative criterion reached), never a threshold move, never a "decorated" gate. The holdout then decided honestly : the same channel measured **0.110, LB 0.026 > 0** — the uncertain devel reading resolved in favour of the mechanism by the sealed data, at which point the CP grid's own condition was satisfied and the verdict is full POSITIF.

**Lesson :** 1) **a secondary/diagnostic shortfall observed on devel must get its verdict mapping before the holdout opens** — the mapping (primary + CP-grid secondary satisfied ⇒ POSITIF ; primary OK + secondary LB ≤ 0 ⇒ PARTIEL + ALERTE) makes the open question measurable instead of arguable ; 2) **a diagnostic channel is published with its CI and never promoted to a primary claim** — changing what the verdict depends on *because* the holdout was favourable would be a threshold move (Lesson 30) in disguise ; 3) **the sealed holdout is the only arbiter a pre-registered risk resolution needs** — the uncertainty you flagged on devel is resolved by the data, and the pre-registered fallback (PARTIEL) is what protects you if the data had gone the other way ; 4) **the strongest evidence is the same-class cold failure** — 20 probe-equivalent tasks fail cold yet all 20 warm-resolve with memory : the condition for "does memory solve the claim" is not the warm hit-rate alone but the paired cold-vs-warm on the class the mechanism claims to fix.

**Application :** 1) at J0/GO time, list every criterion where devel has a real risk of missing a sealed bound and write the exact verdict mapping for each before opening the holdout (the J4 script echoes the mapping and refuses to run before integrity A2 passes) ; 2) keep secondary currency (nodes/P_seq) in the diagnostics with σ-CIs, tag it "SECONDARY diagnostic" in the result JSON, and let the primary claim (probes/P_learn) carry the verdict ; 3) measure the paired cold failure on the same class (fail-cold ∧ warm-resolve) next to warm success — that pairing is the falsifiable core of a memory claim ; 4) when the holdout clears the uncertain channel, say so explicitly in the report (the devel LB ≤ 0 reading and its pre-sealed resolution are part of the record, not a bug).
